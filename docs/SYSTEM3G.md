# 本机 APP 扩到 3 GiB 的离线迁移

这是针对一台 16 GB `016GE2` Mocha 的迁移准备，**尚未完成实机扩容验收**。其他 GPT、32 GB 设备和其他板型不适用。不要在已挂载的桌面系统运行；不改原厂前级引导、boot0/boot1、分区 1–25 或校准数据。

| 分区 | 原起点／扇区数 | 新起点／扇区数 |
| --- | --- | --- |
| APP / p26 | 524288 / 2612431 | 524288 / 6291456 |
| AP1 / p27 | 3136719 / 9009 | 6815744 / 9009 |
| CAC / p28 | 3145728 / 786432 | 6825984 / 786432 |
| UDA / p29 | 3932160 / 26841088 | 7612416 / 23160832 |

每扇区 512 字节。APP 从约 1.25 GiB 扩到 3 GiB，UDA 减少 1884291072 字节；其余分区及所有 GPT 类型／唯一 GUID、属性、名称与文件系统 UUID 保留。新 UDA 为 11858345984 字节，迁移前必须有足够空闲。

顺序是：在独立 RAM 中确认 eMMC 只读且所有分区未挂载，先从可信主机校准内核 UTC 时钟（不写硬件 RTC），再对整盘和 boot0/boot1 做完整电脑备份，独立核对设备端数据与电脑副本、电脑回读 SHA256 和 GPT 两份 CRC。完整镜像包含个人数据、旧系统和设备信息，只放私有备份。不能把文件刚传完或单独 LNX 备份当作整盘备份成功。

本机原有备用 GPT 的条目数组与表头重叠：29 × 128 字节需要 8 个扇区，表头却指向仅提前 7 个扇区的位置，前 28 项与主表相同，第 29 项被备用表头覆盖。主表及两个表头 CRC 正常。原始整盘备份保留此状态，不在备份文件上修补；应先核验完整备份哈希，再将设备保留区内的备用条目数组前移一个空扇区、更新备用表头位置和 CRC，并回读两份表一致。此修复不改分区边界、GUID、主表或文件系统。迁移工具还会拒绝条目数组覆盖表头的布局。

本机用户已允许清理以前安装的其他系统。旧 `/media/0/multirom/roms/L4T_R241` 约 5.8 GiB，清理前要确认完整镜像已验证，并检查当前 Debian 的配置、固件和库是否仍引用该路径；需要的文件应先迁入当前系统。下载、照片、音乐与当前 Debian 桌面不属于旧系统残留。

改 GPT 前先安装并普通启动测试桥接 initramfs。`ramdisk/init-emmc` 只接受 APP 原始大小和 6291456 两个精确扇区数，继续要求相同 eMMC 型号、APP 起点和安装标记；不能先改分区再期待旧检查自动适应。

`tools/grow-app-offline.py` 默认只检查，不执行迁移。它要求私有备份证据、预期 GPT entries SHA256、已实机启动的桥接 initramfs SHA256，并重新检查磁盘身份、无挂载／holders、只读、精确旧布局和空闲空间。工具在写前检查 RAM 时间不早于 APP/UDA 超级块的挂载和检查时间，每次 fsck 后要求检查时间不早于最后挂载。工具不删除文件；`--apply` 需要证据中的桥接启动验收为真。

执行阶段先离线检查 APP/UDA 并缩小 UDA，再从后往前复制重叠区域，每块 fsync 和回读校验；之后复制 AP1/CAC，再更新备用及主 GPT 并核对两份 CRC。内核重新读取分区表后才扩 APP 文件系统，最后检查 APP/UDA 和 UUID，恢复只读。任何中断都必须保持 RAM 运行、保存状态并按已验证完整镜像处理；不能把仍可读的旧 GPT 当作旧 UDA 未被覆盖，也不能盲目重跑迁移。

六项主机测试覆盖不同重叠距离和短尾块、模拟中断后的未复制源区、错误方向拒绝、29 项数组需占 8 个扇区且不能与表头重叠，只更新目标 GPT 边界和 CRC，以及拒绝早于文件系统挂载／检查时间的 RAM 时钟。它们不替代实际 e2fsck、普通启动、桌面与组件验收。最新硬件进度见 [10 月 16 日记录](DIAGNOSTICS-2026-10-16.md)。
