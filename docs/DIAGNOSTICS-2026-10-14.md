# 2026-10-14 原生桌面细节修复

这台原型机的默认启动已使用冷启动验证过的 `6.12.111-moze.1-native`，Niri、native-sync Mesa、Nyxuri/Noctalia 和触屏组件已持久安装。用户确认旋转、触控、实体键、正常开机桌面和密码解锁正常。不是批量设备安装验收；其他面板批次仍需逐机检查。

## 本轮已核对

- Noctalia 亮度映射到实际 backlight，65% 对应 166/255。
- GTK 浮动键盘恢复四行布局，去除高光，实时跟随主题；深浅色新截图与 GTK 配色一致，中文候选仍为独立浮窗。
- 实体返回／主页空操作优化；20 次动作后的 Niri/Noctalia CPU 回到较低空闲水平，5 项导航回归通过。不把导航按钮加入任务栏，不强制窗口装饰。
- ARM Luau 分配对齐修复的真实库回归完成 1,000 次创建／销毁。锁屏密码输入和可信 session-lock 键盘保留。
- 用户一直使用 5 V/2 A 墙充；系统曾读到 500 mA，不应据此称为电脑供电。后续 BC1.2 日志识别 DCP，实读输入限额 2,000,000 µA。未强行绕过充电器检测或提高到超过 2 A。

## 仍在验证

概览底部 Dock 图标的 mipmap 采样失真可重现；关闭 mipmap 的对照恢复正常，原始 SVG 的 CPU 渲染也正常。CPU 生成 mipmap 和 POT 解码候选在实机仍失败，保留为诊断结论，不作为成功修复。只对 Dock 图标使用线性采样的兼容版本已持久安装，SHA256 为 `c375a31ef4ee0f26cc005d0963f9b275142c3ba7998f11ddfe8e82d2d236465a`，全局 mipmap 保持开启，新的实机概览截图中底部 Kitty 图标完整。

内核 DMA-BUF 清单曾显示 162 个对象共 514,248,704 字节，多数无附着设备且来自已经退出的渲染通道。Tegra wrapper 的 scanout PRIME 导入缺少 GEM 句柄释放；候选按句柄计数并在最后一份资源释放时关闭，避免重复导入句柄被重复关闭。

真实 GBM 对照的旧库每批 128 个小缓冲产生 8,388,608 字节残留；新库累计 384 次创建销毁，清单保持 177 个对象、539,013,120 字节（其中含先前桌面残留）。Mesa Gallium SHA256 `5beac318922d10a6ae48e2f84eb1c019b813f3f35146ef0a182aa050318e21e6` 已持久应用并核对 Niri/Noctalia 的实际库映射。桌面重启清除历史残留后，可用内存约 1.2 GiB；20 轮概览开关后缓冲维持 14 个、42,504,192 字节。长期多应用仍需测试，不能将压缩内存配置视作上述释放修复的替代。

0016/0017 补齐 sampler 的两层所有权：借用绑定不消耗 GPU reserve；转交绑定先让 GPU 接管，再释放调用者交出的 wrapper 引用。先前只修 reserve 的候选仍在 20 轮控制中心开关中从 14 个、42,504,192 字节增至 98 个、313,954,304 字节，不能算完整修复。真实离屏 EGL 图像导入／采样对照每批 128 次留下 8 MiB；完整修复累计 384 次只保留当前绑定的 1 个 64 KiB 缓冲，销毁 context 后恢复原计数。最终 Gallium SHA256 `cc81fe6399af38442a48aa52801400086dcb43008aae292353ebac4d65c57fbe` 已持久安装并核对 Niri/Noctalia maps；20 轮概览和 20 轮控制中心开关及随后空闲均保持 7 个缓冲、39,735,296 字节，可用内存约 1.2 GiB。该有限测试不能替代长期多应用检查。

电源键实际检测 DPMS 与背光，避免 On/零亮度时反复进入熄屏。禁用 logind 默认短按关机；用户确认熄屏、再次短按唤醒及触控密码解锁正常。11 项按键回归通过，未重启或绕过锁定会话解锁。

当前默认 native 内核关闭 CPU_FREQ、CPU_IDLE、ZRAM。新的 `native-runtime` 开启 Tegra124 CPUFreq/DFLL、schedutil、LZ4 zram、PSI/MGLRU，沿用原厂频率／电压表。完整内核、模块、DTB 已构建并校验，使用独立 UDA 路径，尚未替换默认启动。

DFLL 开启的首次试验没有获得 SSH 连接，用户观察黑屏／启动图案；不能仅由此证明内核崩溃。相同内核搭配已验收的 DFLL 关闭设备树、`cpuidle.off=1` 后，两次进入 Debian，USB SSH 正常，PLL_X 保持 696 MHz，没有 CPUFreq policy。候选模块位于数据分区，早期 udev 无法加载尚未挂载路径中的无线模块；挂载后加载匹配的 brcmfmac，Wi-Fi SSH 恢复。临时背光诊断服务同样缺少挂载依赖，修正 `RequiresMountsFor=/srv/mocha-data` 后加载匹配背光，DSI connected/enabled、framebuffer 建立。以上不能作为 DFLL 动态调频通过的证据。

关闭 DFLL 的对照中，384 MiB 逻辑容量的 LZ4 zram 已实际启用；仅对测试进程自身 32 MiB 匿名页执行 pageout，再读回并验证 SHA256 一致。页内容避免同值页优化，pageout 时 zram 原始数据 33,820,672 字节、压缩数据 475,201 字节、实际内存 544,768 字节；含少量其他系统交换页。MGLRU 实读 `0x0001`、PSI 可读。没有制造全系统内存耗尽或闪存交换，此结果只证明有限压缩／读回正确性，长期多应用压力、调频、电压和 CPU idle 仍待验收。

挂载完成后加载这版内核匹配的 Nouveau，临时服务配置按名称排序放在旧默认配置之后，避免旧配置覆盖模块路径。完整 Niri/Nyxuri 启动，Gallium/EGL/GBM 实际 maps 均来自上述最终修复库；用户确认桌面、触控和概览图标正常。20 轮概览、20 轮控制中心及随后空闲均为 8 个 DMA-BUF、40,685,568 字节，可用内存约 1.2 GiB。供电实读 DCP 2 A，GPU 使用原厂 852 MHz；CPU 固定 696 MHz。这是 DFLL 关闭的临时对照，未替换默认引导。
